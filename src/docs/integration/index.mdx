# Integration Guide

> **Audience:** Project issuers deploying a vesting program on Minke Finance.
> **Time:** ~15 minutes end-to-end (plus approval wait).

---

## Overview

Minke Finance supports two pool types. Both follow the **same two-stage creation flow** — Create Oracle, then Create Vault. The difference is in how the oracle is configured.

| Pool Type | Best For | Oracle Config |
|---|---|---|
| **Standard Pool** | Token vesting, airdrops, lock-up programs — issuer mints VT directly to investors | Piecewise release schedule (LINEAR / PIECEWISE) |
| **Custom Pool** | Farming, DePIN, loyalty — investors deposit an asset to earn VT at a declining rate | Rate-decay curve (CURVE) |

Both pool types share the same **DFI Oracle**, **VT Token**, and **Redeem Pool** architecture. The issuer deposits DFI tokens T, approves the Redeem Pool, and investors claim T by staking VT.

## Workflow at a Glance

```
Connect Wallet
  → Getting Started: Create Oracle (3 steps) — configure & deploy on-chain, submit GitHub Issue
  → [Wait for Minke team approval]
  → Getting Started: Create Vault (2 steps) — select oracle, launch vault
  → Standard Pool: deposit T, approve pool, mint VT to investors
  → Custom Pool:   deposit T, approve pool, let investors deposit
```

<Callout type="warning" title="5% Protocol Fee">
All investor claims are subject to a fixed 5% protocol fee. Investors receive 95% of their entitled tokens on each claim.
</Callout>

## Prerequisites

- A wallet connected to the **target EVM network** (MetaMask or any WalletConnect-compatible wallet).
- Your **DFI token (ERC-20) address** — the token you will vest.
- For **Custom Pool** only: the address of the deposit asset (ERC-20, ERC-721, or ERC-1155) on the same network.
