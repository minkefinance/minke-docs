# Key Concepts

This page defines the core terminology used throughout Minke's documentation.

## Asset Types

### DFI — Deterministic Future Income

A future income stream where the amount and schedule are known in advance. Examples:
- Token vesting schedules (cliff + linear)
- SAFT / investor allocation tranches
- Node license emission schedules
- Mining reward agreements

DFI is the primary asset class Minke Phase 1 handles. Because the schedule is deterministic, no oracle is needed.

### VFI — Variable Future Income

A future income stream where the amount depends on external factors — utilisation rates, price feeds, governance decisions. Examples:
- Liquid staking yields (stETH)
- AMM LP fees
- Lending protocol interest

VFI requires Minke Phase 2 (Yield Token). Phase 1 VT is not suitable for VFI.

## Pool Types

Both pool types are created through the same two-stage flow: **Create DFI Oracle → Create Vault**. The mode is chosen when configuring the oracle.

### Standard Pool

A pool where the **issuer mints VT directly** to each investor. Components:
- `DFIOracle` — LINEAR or PIECEWISE release schedule (configured in Create Oracle step)
- `PoolVault` — holds DFI tokens T
- `VTToken` — the pool's ERC-20 vesting token
- `RedeemPool` — T distribution and staking contract

Best for: token vesting programs, airdrops, lock-up schedules.

### Custom Pool

A pool where **investors deposit an asset to receive VT** at a declining rate. Components:
- `DFIOracle` (CURVE mode) — rate-decay curve defining VT per asset over time (configured in Create Oracle step)
- `CustomVault` — accepts investor deposits, mints VT at the current oracle rate
- `VTToken` — the pool's ERC-20 vesting token
- `RedeemPool` — T distribution and staking contract

Best for: farming programs, DePIN rewards, loyalty programs.

## Protocol Primitives

### DFI Oracle

A per-pool EIP-1167 clone storing all release schedule or rate curve data. Created first, before the vault is deployed. Three modes:

| Mode | Used by | Description |
|---|---|---|
| LINEAR | Standard Pool | Constant release rate between start and end |
| PIECEWISE | Standard Pool | Stepped or ramped milestones (up to 6 breakpoints) |
| CURVE | Custom Pool | Declining VT-per-asset rate from Base Rate to Min Rate |

### VT — Vesting Token

A fungible ERC-20 representing a claim on the underlying token T within a specific pool. VTs are:
- Minted only by the Vault (Standard Pool: `mintVT` by issuer; Custom Pool: on investor `deposit`)
- Burned only by the RedeemPool (on T distributions) or at Maturity (`redeemVT`)
- Freely tradable as a standard ERC-20

### YT — Yield Token (Phase 2)

A future token type designed for VFI streams with variable yield. Not yet live — see the roadmap for planned release.

### RedeemPool

The staking and T-distribution contract deployed alongside each pool's VTToken. VT holders stake VT here; the pool lazily pulls T from the vault per the DFIOracle schedule, burns VT 1:1 as T arrives, and distributes T to stakers proportionally. A protocol fee is deducted from each distribution. After vesting ends, `redeemVT()` enables 1:1 Maturity redemption from the pool's `excessT` reserve.

## Staking Mechanics

### Shares

When a user stakes VT in the RedeemPool, they receive shares at the current share-to-VT ratio. As VT is burned during T pulls, share value (in VT terms) decreases. Withdrawals from the RedeemPool are denominated in shares (`unstakeVT(shares)`), not VT amount.

### accVTPerShare

A global accumulator tracking cumulative VT burned per share. Increases each time a T pull occurs and VT is burned. Used to calculate each staker's proportional pending claimable T.

### claimableT

The T amount accrued to a staker, calculated as their proportional share of all T pulled since their last interaction, minus the protocol fee. Transferred to the staker when they call `claimT()`.

## Economic Terms

### Present Value (PV)

The market-determined value today of a future cash flow. In Minke, VTs trade at a discount to par (1 underlying) until maturity. The discount reflects time value and risk.

### excessT

T accumulated in the RedeemPool when more T arrives from the vault than VT can be burned (e.g., near dust protection limits). Reserved for Maturity `redeemVT()` at 1:1.

### Protocol Fee

A fixed 5% fee deducted from T distributions to RedeemPool stakers (investors receive 95%). Not charged at VT minting or at Maturity redemption.
