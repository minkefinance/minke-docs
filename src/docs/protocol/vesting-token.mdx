# Vesting Token (VT)

A Vesting Token (VT) is a fungible ERC-20 representing a claim on the underlying DFI token (T) within a specific pool. VTs are minted either by the issuer (Standard Pool) or automatically when investors deposit assets (Custom Pool).

## How VT is Minted

### Standard Pool — Issuer Mints Directly

In a Standard Pool, the project owner calls `mintVT` to allocate VT to each investor:

```solidity
function mintVT(address to, uint256 amount) external onlyProjectOwner;
```

Each investor receives VT proportional to their vesting allocation. The issuer controls the distribution — no NFT staking or intermediary step required.

### Custom Pool — Investor Deposits

In a Custom Pool, investors deposit an asset and receive VT at the current oracle rate:

```solidity
function deposit(uint256 amount) external; // ERC-20 deposit
```

The rate is defined by the pool's `DFIOracle` (CURVE mode) and declines over time. Earlier depositors receive more VT per unit deposited.

## What VT Holders Can Do

### Option A — Stake in RedeemPool

Stake VT in the pool's `RedeemPool`. The pool automatically pulls T from the vault per the DFIOracle schedule and distributes it proportionally, minus the protocol fee (e.g. 5%):

```solidity
function stakeVT(uint256 amount) external;
function claimT() external;
function unstakeVT(uint256 shares) external;
```

See [RedeemPool](/protocol/redeem-pool) for full mechanics.

### Option B — Trade on AMM

VTs are standard ERC-20 tokens. Holders can sell them on any DEX. Secondary buyers get discounted exposure to the underlying vesting stream.

### Option C — Wait for Maturity

Hold VT until the vesting schedule ends. Call `redeemVT()` on the RedeemPool for 1:1 redemption with no fee.

## Maturity: 1:1 Redemption

Once the release schedule has fully completed and `vestingEnded` is set to `true` on the RedeemPool, VT holders can redeem:

```solidity
function redeemVT(uint256 vtAmount) external;
```

Burns `vtAmount` VT 1:1 from the RedeemPool's `excessT` reserve. No protocol fee.

<Callout type="tip">
Redemption at maturity is always exactly 1:1, with no protocol fee. VT holders who did not stake during the vesting period can still redeem their full par value at maturity.
</Callout>

## VT Token Properties

| Property | Value |
|---|---|
| Standard | ERC-20 |
| Minting (Standard Pool) | Only PoolVault, via `mintVT(to, amount)` called by project owner |
| Minting (Custom Pool) | Only CustomVault, on investor `deposit()` |
| Burning | RedeemPool (on T pull) or Vault (Maturity `redeemVT`) |
| Transferability | Fully transferable — no restrictions |
| Decimals | Matches the underlying token |

## Lifecycle Summary

```
Issuer deposits T → Vault
         ↓
Standard Pool: Issuer calls mintVT(to, amount) for each investor
Custom Pool:   Investor calls deposit(amount) → VT at rateAt(now)
         ↓
     Vesting period (active)
  ┌──────────────────────────────────────────────────┐
  │  Stake VT in RedeemPool                          │
  │  → Pool pulls T from Vault per DFIOracle          │
  │  → Burns VT 1:1, distributes T (minus fee)        │
  │  → claimT() to receive T                          │
  │  OR                                               │
  │  Sell/trade VT on AMM at market price            │
  └──────────────────────────────────────────────────┘
         ↓
     Maturity (vestingEnded = true)
  redeemVT() → 1:1 T from excessT (no fee)
```
